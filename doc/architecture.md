# 화면과 가격 모델

상품 화면에서 우유를 골라 **실제 구매 기록**을 누르면 선택한 상품과 가격이 가계부 탭으로 전달됩니다. 가계부 탭은 유효한 참고 가격과 상품명을 입력란에 표시합니다. 상품 구매에서는 식료품 지출과 구매 수량을 표시하고, 외식·수입에서는 식당·입금처를 표시합니다. **내역 저장**을 눌렀을 때만 가계부 서비스가 거래를 저장합니다.

## 화면별 책임

| 화면 | 담당 클래스 | 맡은 일 |
|---|---|---|
| 창 | [LedgerFrame](../src/sgl/LedgerFrame.java) | 다섯 탭 구성, 이동·종료 확인, 공통 월과 새 가격 반영 |
| 가계부 | [LedgerTab](../src/sgl/LedgerTab.java) | 수입·지출 입력, 선택한 거래 수정, 월 합계 |
| 예산 · 장보기 | [BudgetTab](../src/sgl/BudgetTab.java) | 예산 입력, 항목 편집, 장보기 초안·저장 |
| 상품 · 할인 | [ProductTab](../src/sgl/ProductTab.java) | 상품 선택, 가격 직접 입력, 비동기 공식 가격 수집·수집 목록 창 |
| 가격 비교 · 이력 | [PriceTab](../src/sgl/PriceTab.java) | 단위 가격 순위, 기간·지점 선택, 이력 그래프 |
| 구매 목표 · 알림 | [TargetTab](../src/sgl/TargetTab.java) | 개인 목표 편집, 충족 가격과 알림 확인 |

각 탭은 자기 입력란과 선택 상태를 보유합니다. 공통 상위 클래스 `TabView`의 `hasDraft()`와 `discardDraft()`를 통해 창이 이동 전에 미저장 편집을 확인합니다. [CD01 창과 탭의 책임](class-storage-ui.png)

## 상품과 가격

`Product`는 상품 ID, 품목, 규격, 낱개 용량, 단위와 묶음 수를 보유하는 불변 Java 레코드입니다. `unitPrice`는 묶음 가격을 기준 단위로 환산합니다. 우유 1,000ml 한 팩이 2,600원이면 100ml당 가격은 260원입니다. `comparableTo`는 포장 개수가 다른 경우에도 품목, 브랜드, 규격, 낱개 용량과 단위가 일치하는지 확인합니다. [Product 소스](../src/sgl/Product.java)

`PriceObservation`은 어느 상품의 가격을 언제, 어느 마트·지점에서, 어떤 조건으로 확인했는지 기록합니다. 금액은 `BigDecimal`, 확인 시각은 `OffsetDateTime`입니다. 행사 기간과 확인 후 24시간 경계를 검사해 현재 유효 여부를 판정합니다. 상품·비교 탭은 이 객체와 상품이 들어 있는 `OfferRow`를 표시합니다. 가격이 없는 카탈로그 항목의 관측값은 null이며 상품 탭에 가격 미확인으로 표시됩니다. [가격 관측 소스](../src/sgl/PriceObservation.java) · [CD03 저장 상태와 불변 가격 모델](class-domain.png)

## 저장과 서비스 API

`AppState`는 상품을 ID로 찾는 `Map<String, Product>`와 가격 관측 목록 `List<PriceObservation>`을 보유합니다. `Repository`가 읽기·쓰기를 담당하며 JSON 파일의 기존 필드 이름과 버전 1 구조를 사용합니다. 상태 복사본은 독립된 컬렉션을 갖고 불변 상품·관측값을 공유합니다. [상태](../src/sgl/AppState.java) · [저장소](../src/sgl/Repository.java)

다섯 기능 서비스와 수집 조정·목록 관리 서비스는 같은 저장소와 시계를 사용하는 `Service`를 상속합니다. `ProductService`는 상품 조회·직접 입력·즐겨찾기를 담당합니다. `OnlineCollectionService`가 `ProductCollector`를 통해 공식 페이지를 수집하고 새 가격을 저장한 뒤 `TargetService`에 목표 판정을 요청합니다. `OnlineCatalog`가 수집 목록과 출처별 오류를 관리하고, `HttpPageClient`와 `OfficialPageParser`가 제한된 HTTP 읽기와 상품 ID·규격·가격·재고·조건 검증을 수행합니다. 공개 서비스 요청·결과와 JSON 입출력은 기존 맵 계약을 사용합니다. 입력 키, 결과 상태와 오류는 실행 창의 Javadoc API 매뉴얼에서 확인할 수 있습니다. [CD02 유스케이스를 구현하는 서비스 클래스](class-services.png) · [빌드와 검증](verification.md)

직접 입력과 피드의 관측은 출처별로 보존됩니다. 같은 시각이면 직접 확인 기록을 우선하며, 피드 갱신 실패가 별도 직접 입력 기록을 삭제하지 않습니다. 가격 조회 조건이 바뀌면 이전 결과를 비우고, 배경 갱신은 선택한 상품·지점을 유지합니다.


## 수집 중 저장 보호

HTTP 읽기는 저장소 잠금 밖에서 수행합니다. 응답을 받은 후 최신 상태를 다시 읽고 가격만 합쳐 저장하므로, 다운로드 중 입력한 가계부·예산·즐겨찾기를 이전 복사본으로 덮어쓰지 않습니다. 버튼은 수집 중 중복 요청을 막고 SwingWorker가 화면 응답성을 유지합니다. 수집 성공 뒤 03·04·05와 장보기 예상액을 갱신합니다.

수집 실패는 해당 웹 출처 관측만 현재 비교에서 제외하고 과거 이력과 독립적인 직접 입력을 보존합니다. 자동 시도 날짜와 마지막 성공 시각을 따로 저장하며 수동 버튼은 같은 날에도 재시도할 수 있습니다. `MartAdapter`의 로컬 파일 API는 기존 자료 호환과 테스트에만 남아 있고 파일 연결 버튼은 제공하지 않습니다.


## 사용자가 선택하는 수집 목록

`CollectionDialog`는 검색·확인·등록과 목록 관리를 담당합니다. `ProductDiscovery`는 공식 검색 응답에서 상품 링크를 찾고, 상세 페이지의 상품 ID와 이름·브랜드·판매 묶음 규격을 확인합니다. 미리보기는 저장하지 않으며 `CollectionListService.add`에서 사용자가 확인한 상품과 실제 가격, 향후 수집 설정을 한 번에 저장합니다. 규격을 자동으로 확정할 수 없으면 총 용량·개수 확인이 필요합니다.

`CollectionSource`는 `Product`, 온라인몰, SKU, 정규화한 상세 URL과 활성 상태를 보유하는 불변 레코드입니다. `AppState`의 설정에 목록을 보관합니다. 설정이 없는 기존 파일만 기본 8개를 사용하고, 사용자가 비운 목록은 빈 상태로 유지합니다. `ProductCollector`는 선택한 목록을 전달받으며 `OnlineCatalog`는 활성 항목만 요청합니다.

검색은 최대 40개 결과, 수집 목록은 최대 100개입니다. 검색과 HTTP 요청은 SwingWorker에서 실행합니다. 수집 중 사용자가 항목을 중지·삭제하면 늦게 도착한 해당 응답은 반영하지 않습니다. 상품 규격이 바뀌면 수집 오류로 표시하며 삭제 후 새 규격으로 등록할 수 있습니다. 새 규격은 독립 ID를 사용해 과거 가격과 거래를 보존합니다.

## 신규 상품의 화면 선택 상태

PriceTab은 비교 기준 상품과 이력 조회 상품을 구분합니다. 상품을 바꾸면 해당 상품의 판매 조건·마트·지점을 적용하고, 비교표 행을 선택하면 그 행의 실제 상품 ID로 이력을 조회합니다. 같은 선택 상태에서 백그라운드 가격만 갱신할 때는 사용자가 지정한 이력 지점을 유지합니다.

TargetTab은 관심 상품 추가 후 editingTargetId와 선택 행을 해당 상품에 맞춥니다. 미저장 목표가 있으면 이동 전에 확인하고 취소하면 입력과 상품 ID를 함께 보존합니다. 긴 상품명은 입력 컨트롤과 다른 줄에 표시합니다. 수집 설정은 목표·관심 목록과 독립적입니다.

## 수량과 미저장 목표의 보존

ProductDiscovery.packageTotal은 명시적인 앞뒤 묶음 배수를 적용하고 모호한 수량은 확인 대상으로 남깁니다. TargetTab은 정렬로 선택 행 위치만 바뀔 때 편집 중인 값을 다시 불러오지 않습니다. PriceTab과 TargetService의 초기 판매 조건은 가장 최근 관측을 기준으로 하며 저장한 목표 조건이 우선합니다.

## 최소 주문과 창의 수명

PriceObservation.minimumQuantity는 수집된 가격 조건의 최소 판매 묶음 수를 반환합니다. BudgetService는 계획 수량이 이 값보다 작으면 해당 가격을 예상액에서 제외하고 estimateReason을 반환합니다. BudgetTab은 이유를 예상액 칸에 표시합니다. 상품 규격·단가와 실제 결제 기록은 독립적으로 유지합니다.

LedgerFrame.dispose는 ProductTab.close를 호출합니다. ProductTab은 닫힘 상태를 설정하고 OnlineCollectionService.close로 이후 저장을 차단한 뒤 SwingWorker를 취소합니다. 서비스의 닫힘 확인과 저장은 같은 Repository 잠금 안에서 처리하므로 이미 시작한 저장만 종료 전에 완료됩니다. 네트워크를 기다리느라 저장 잠금을 잡지 않으며 늦은 응답은 반영하지 않습니다. 닫힌 탭의 진행·완료 콜백은 화면이나 알림 창을 갱신하지 않습니다.

## 검색 선택과 목표 편집

CollectionDialog는 selectionRevision으로 검색·상세 확인 요청 시점의 선택과 현재 선택을 대조합니다. 상품 행·주소·검색 조건이 바뀌면 미리보기와 등록 버튼을 해제하며 이전 선택의 지연 응답을 표시하지 않습니다. 등록·중지·재개 후에는 수집 출처 키로 같은 행을 선택합니다. ProductTab.selectRegisteredProduct는 새 상품이 기존 필터에 가려지지 않도록 표시합니다.

TargetTab은 적용 기준이 없는 항목을 기준 없음으로 표시합니다. targetDirty인 동안 수동 알림 평가를 막아 저장된 이전 목표로 알림 이력을 소모하지 않게 합니다. 목표 저장과 새 알림 없음은 상태 표시줄에 안내합니다. TargetService의 저장된 목표 평가 계약은 유지합니다.

## 서비스 호출 순서

서비스 요청과 결과는 `Map<String, Object>`입니다. 상품은 `Product`, 관측은 `PriceObservation` 레코드로 표현합니다. 그림의 FN05는 `TargetService.managePurchaseTargets`를 뜻합니다. 입력 키와 상태값의 전체 계약은 Javadoc을 확인하세요.

- 입력을 검증한 뒤 거래를 저장하고 해당 월의 합계를 반환합니다. [SD01 실제 지출 저장](sequence-ledger.png)
- 장보기 계획을 저장하면 소계와 남은 예산을 계산합니다. 조회하거나 초안을 편집하는 동안에는 저장을 보류합니다. [SD02 예산과 장보기 계획 저장](sequence-budget.png)
- 활성 목록의 가격을 수집하고 판매처별 성공·실패 결과를 반환합니다. 사용자는 상품 화면에서 재시도할 수 있습니다. [SD03 상품 가격 자동 수집과 재시도](sequence-collection.png)
- 같은 규격과 판매 조건으로 단가를 환산해 현재 순위와 날짜별 이력을 조회합니다. [SD04 현재 가격 비교와 과거 통계](sequence-prices.png)
- 새 가격을 저장하면 목표 충족 여부를 평가하고 당일 알림 기록을 저장한 뒤 알림을 표시합니다. [SD05 목표 가격 도달 알림](sequence-targets.png)
- 검색한 상품의 규격과 가격을 확인하고 등록하면 향후 수집 목록에 포함됩니다. [SD06 상품 검색과 수집 목록 등록](sequence-discovery.png)

그림은 주요 호출 순서를 요약합니다. 숫자는 본문과 대응하는 메시지 번호이며 생략된 사용자 입력 메시지는 화면 설명을 참고하세요. 함수의 시각은 생성자에 주입한 Clock에서 구합니다. 별도의 Request/Result 클래스나 PriceUpdated 이벤트 버스는 없습니다. 단가 나눗셈은 BigDecimal의 DECIMAL128 정밀도로 수행하고 화면 표시 자릿수는 따로 적용합니다.
